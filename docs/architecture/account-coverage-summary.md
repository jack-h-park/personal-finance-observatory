# Read-only account coverage summary and section navigation

Status: merged in #347 and separately deployed with bounded owner-web verification; no private inventory adoption or completeness acceptance. Implements the [approved scope](../product/account-coverage-follow-up-scope.md) after #346; see [release acceptance](../operations/installation-status.md#coverage-summary-release-acceptance-november-17-2026).

## Pure presentation contract

`lib/application/account-coverage-summary.ts` exports `summarizeAccountCoverage({ investmentRows, supplementaryRows })`. Inputs are readonly structural projections of existing adapter rows: status, supplementary kind and optional recorded historyGap. Adapter types are imported with `import type` only. The function has no filesystem/database/config/clock/network dependency, validation fallback, identity joining or mutation.

It returns investment, bank/CMA and other supplementary groups. Each has the supplied row count, five existing review-state buckets and an independent count of rows carrying historyGap. Banks/CMA are existing deposit/cma kinds; the other group includes pension, gold and gold-price rows. No configured row becomes an expected account, confirmed owner, closed account, inferred zero or newly required source. Empty groups mean no configured rows in this input, not a reviewed empty economic inventory.

Status classification remains entirely with existing adapters. In particular, a recent date never clears an unknown query period, and the helper never changes a supplied review status. The existing bank gap handler overwrites combined status with action_needed. The earlier #347 surface did not expose independent pre-gap freshness, so it labelled that limitation and linked to recorded dates rather than reconstructing from a date or partial flag. The [additive freshness contract](supplementary-coverage-freshness.md), merged in #350, supplies a separate read-only display consumer. The existing combined projector/output remain unchanged; an additional supplementary freshness table consumes a separate pure projection. Both are now deployed through the separately accepted November 18 isolated release; the #347 limitation describes the earlier release only. Overlapping gap/status signals are not summed into a unique-account total. The summary intentionally has no combined completeness metric or global all-current result. It does not expose dates, labels, paths, financial amounts or raw action strings.

## Surface and navigation

The bilingual server component `AccountCoverageSummary` appears before the existing `/data-ops` update sections. It counts the already loaded `getAccountCoverage().rows` and `getSupplementaryCoverage().rows`; there is no additional inventory adapter query, new cache or backend endpoint. It presents groups and status counts separately with an explicit overlap/scope notice. Thresholds, reminder/action queue and confirmation controls are unchanged. The November 18 supplementary detail table adds freshness and recorded-gap columns without changing its existing status/action behavior.

Group links target existing `#account-coverage` and `#supplementary-coverage` sections. A separate `/accounts#inventory-review` link explains that inventory scope/ownership requires its own review; it does not load or assert an inventory-review state. `AccountInventoryReview` retains source/investment links and adds a labelled bank/CMA/supplementary link. Existing unknown-owner and pension-policy rendering is unchanged. The summary neither repairs private metadata nor establishes an atomic cross-file/DB observation.
